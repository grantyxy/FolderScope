FolderScope

v1.0.0-preview.1 · Windows x64 · 2026-10-23

An open-source alternative to FolderSizes, independently rewritten in C# / .NET Framework. This preview does not promise full feature, UI or file-format parity. Source: grantyxy/FolderScope.

Start and choose a language

Run FolderScope.exe with FolderScope.exe.config in the same directory. It uses .NET Framework 4.8 and needs no Python, Node.js, server or reference product. The upper-right 中文 / EN menu switches between Simplified Chinese and English immediately without discarding the scan. The preference is saved. Filenames, paths and owner identities retain their original values.

Scan and explore

Enter a local or UNC path and click Start, or use Browse. Paths accepts multiple roots, one per line. Overlapping roots are normalized to prevent duplicate traversal. Pause, resume and stop controls are available. A stopped scan is marked partial. Check Event Log for inaccessible paths, skipped reparse points, allocation estimates and depth limits.

Double-click folders in Details or folder regions in the four charts to explore. Column headers sort results. Right-click for file operations and column visibility. Size reports logical bytes. Size on Disk uses Windows allocation metadata. Units use powers of 1024. Hard links are counted per directory entry, so sums do not represent unique physical volume usage. Metadata and reserved storage are outside folder-file totals. Reparse-point file allocation is reported as unknown (displayed as 0 plus an event), not confirmed zero usage.

Scanning engines

Local NTFS MFT reading is enabled by default and generally requires administrator privileges. Unavailable MFT access, unsupported file systems, network paths or read failures fall back to parallel directory enumeration. The status bar identifies the actual engine. MFT mode may read a whole volume's MFT before selecting a subfolder, so it is not always faster. Disable MFT in Options if needed. The local release self-test covered directory enumeration without elevation, not a full MFT validation.

Reports and search

Fifteen file reports cover largest, oldest, newest, temporary, duplicate, type, category, attributes, owners, size, name, age, depth, year and non-business files. Empty folders and long paths are additional reports. Set the row limit to 0 for all results. Owner collection is disabled by default; enable it before scanning when needed.

Duplicate modes compare name, name and size, name/size/modification time, or SHA-256 content. Metadata matches do not prove identical content. Content comparison reads candidates and reports failures. Selection assistance only selects records.

Search supports wildcard and regex patterns, numeric sizes and allocation, depth, path/name length, file counts, modification age, attributes and owners. Include rules are OR-combined; exclusions take priority. Report and search paths scope existing data. Use Scan first to refresh the filesystem.

During scanning, folder rules prune whole branches before traversal. Folder inclusion rules can therefore exclude unmatched ancestors. Folder size, allocation and file count rules require a completed scan and must be applied in Search. Filtered-out contents never make a directory qualify as truly empty.

Snapshots and exports

Save Results writes a metadata-only .fsscan file. Offline snapshots support browsing, search and comparison while blocking changes to live files. FolderScope snapshots are not compatible with the original product's files. Trend Analyzer compares multiple captures, and Disk History records local drive capacity observations.

Export headers and category labels follow the interface language; filenames, paths and owner names retain their original values. Exports include real XLSX workbooks, CSV, HTML, PDF, XML and TXT. Charts export to PNG. PDF pages are rasterized to preserve Unicode rendering; text is not searchable or selectable. Long paths are abbreviated in PDF. Use CSV, XLSX or XML for complete machine-readable paths.

File operations

Open, reveal, copy, move, rename, Recycle Bin and ZIP operations are available for live results. Changes to scanned files are checked before operations. Move and delete require an in-app confirmation. Windows manages Recycle Bin availability. ZIP encryption is not implemented. Existing ZIP files are not overwritten. A failed copy/archive may leave partial destination content; read the error and inspect the target.

Scheduled reports and email

Once, daily and weekly tasks use Windows Task Scheduler under the signed-in current user. Tasks must be recreated after moving the application. Run now executes the specified job and sends email if enabled. Share discovery uses the current Windows identity and does not manage credentials.

Configure SMTP in Options. Passwords are protected with Windows DPAPI for the current user. Port 587 with STARTTLS is the common supported configuration; implicit TLS on port 465 is not implemented. Email is sent only by an explicit Send action or an email-enabled job you run or schedule. Actual network-share scans, SMTP delivery and timer-triggered Windows tasks have not been validated for this release.

Shortcuts

F5 refreshes, Esc stops a scan, Ctrl+O loads, Ctrl+S saves, Ctrl+F opens Search, F1 opens this guide, Alt+Left goes back, Alt+Up navigates upward. Ctrl+C copies selected report rows and Delete requests a Recycle Bin operation.

Storage and building

Settings, disk history, job definitions and logs are under %LOCALAPPDATA%\FolderScope. Source files are in src. Run build.ps1 to rebuild with the Windows .NET Framework compiler.

Optional command-line use

FolderScope.exe --scan "D:\Data" --snapshot "D:\Reports\scan.fsscan" --export "D:\Reports\details.xlsx"
FolderScope.exe --scan "D:\Data|E:\Data" --report "Largest Files" --export "D:\Reports\large.csv"
FolderScope.exe --scan "D:\Data" --report "Duplicate Files" --duplicate-mode "Content (SHA-256)" --export "D:\Reports\duplicates.html"
FolderScope.exe --job "C:\Path\job.xml"

Exit codes: 0 finished, 1 error, 3 cancelled. Review the adjacent .events.txt output for skipped or inaccessible data even when the process returns 0.
